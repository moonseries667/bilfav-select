# 发给外部 AI 的分类表生成 Prompt

将下面的 Prompt 与已导出的 `video-dataset.json` 一起发给外部 AI。生成结果可直接粘贴到步骤 3 的「粘贴外部 AI 的分类表 JSON」，点击「载入到分类列表」，或保存为 JSON 后导入。普通类别上限可在 Prompt 中自行修改。

```text
请根据我附上的 Bilibili 收藏视频数据，为我生成一份按个人兴趣整理收藏夹的分类表。

我的分类偏好是：MMD、绘画、MAD、科普、娱乐、漫画等。优先采用这些直观、方便查找的名称，根据实际数据补充必要类别。不要强制套用电影、动画、知识等统一的内容性质体系。

任务要求：
1. 分析所有可用视频的标题、简介、完整 tags、分区、UP 主和时长；unavailable=true 的记录跳过。不要仅根据第一个标签或旧收藏夹名称分类。若你无法完整读取附件，请说明缺失范围，不要假装分析过全部数据。
2. 最多生成 12 个普通类别，数量可以少于上限。相近类别尽量合并，避免按单个角色、UP 主、作品名或零散主题创建大量收藏夹。
3. 程序会让每个视频只进入一个类别，因此每类 description 必须写清：收录内容、主要排除内容，以及与相邻类别冲突时如何判断。判断依据应是视频主要内容，不是仅提及的主题。
4. 请明确处理 MMD 与 MAD、绘画与漫画、科普与专项教程的边界。我的初始偏好：MMD 制作教程归 MMD；漫画绘制、上色与绘画技法教学归绘画；漫画作品阅读、剧情解读与评论归漫画。其他交叉情况也要在对应 description 中说明，避免循环或矛盾的优先规则。
5. 娱乐仅收录以搞笑、综艺等娱乐内容为主的视频；符合其他专门类别时优先按其定义处理。不要把娱乐变成所有无法判断内容的兜底。
6. 不生成“不确定”“其他”“未分类”等兜底类别，程序会自动保留“不确定”。description 可说明：信息不足或仍无法可靠区分时交由程序归入“不确定”。
7. 只生成分类表，不逐条输出视频分类。不要生成子类、树形结构或多标签。

输出格式：
只返回一个严格 JSON 数组，不要 Markdown 代码围栏、前言或解释。每项只能包含两个字符串字段 name 和 description；名称简短、唯一，说明完整、可直接作为分类规则。

格式示例：
[
  {"name":"类别名称","description":"收录范围；排除范围；与相邻类别冲突时的判断规则。"}
]
```
